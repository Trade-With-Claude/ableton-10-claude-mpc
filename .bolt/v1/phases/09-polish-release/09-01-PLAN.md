## Acceptance Criteria

### AC-1: Robust connection and clear errors
- **Given**: the MCP server with the fake Live
- **When**: `uv run pytest -q` runs
- **Then**:
  - **Write commands are never sent twice.** Before sending, the client checks whether a cached socket is dead (non-blocking `MSG_PEEK` reads EOF or an error) and reconnects first. If the connection breaks *after* a write was sent (`apply`, `create_instrument_track`, `record_automation`, `transport`, …), the client does not resend. It raises: "connection lost after sending '<cmd>'; it may or may not have been applied. Check with get_session."
  - **Read-only commands** (`ping`, `get_session`, `get_device_params`, `get_meters`, `get_wavetable`, …) keep their single transparent retry.
  - **Error messages say what to do:**
    - **Connection refused:** Live closed, or ClaudeMPC not selected in a Control Surface slot (Preferences › Link/MIDI), or the port is taken (`CLAUDE_MPC_PORT`).
    - **Timeout:** Live may be busy or blocked by a dialog. Click in Live and retry.
    - **Lost connection:** Live quit or the surface was re-selected.
  - **Version check:** the server reads the expected `SCRIPT_VERSION` from `remote_script/ClaudeMPC/commands.py`.
    - `ping` adds `expected_script_version`.
    - When the versions differ, `ping` adds a `warning` telling the user to run `scripts/install.sh` and restart Live. Other tools do not fail.
  - **Tests:**
    - an `apply` is not resent after a dropped reply;
    - `get_session` reconnects after the server restarts;
    - a dead cached socket is detected before sending;
    - the timeout message;
    - the version-mismatch warning.
- **Verify**: `uv run pytest -q`
