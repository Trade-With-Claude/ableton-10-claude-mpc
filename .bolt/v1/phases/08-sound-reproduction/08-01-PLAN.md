# PLAN — Phase 8: Sound Reproduction

## Goal
Dorian points at a sample ("reproduce the sample on the test track") and Claude builds a starting point in Live:
- a new MIDI track with a stock synth set up to sound like the sample;
- the notes and rhythm as a session clip;
- stock effects where the analysis calls for them, plus Phase 7 automation where the sound moves.

The first target is the Phase 7 test sample, `TSP_SL_172_synth_lead_tension_F#.wav`, on track 33 "test".

## Research (2026-10-20, on the target sample)
- **The sample:**
  - `~/Documents/sample/TSP_SL_172_synth_lead_tension_F#.wav`, 44.1 kHz stereo, 5.58 s = 16 beats at 172 BPM (4 bars).
  - Spotlight (`mdfind -name`) finds it by file name.
  - Live 10 can't list Arrangement clips (`arrangement_clips` came with Live 11), so the file is found by name/path, not through Live.
- **basic-pitch (Spotify) is ruled out:**
  - Its macOS deps (`tensorflow-macos<2.15.1`) have no Python 3.13 wheels. It only runs in a separate Python 3.11 env, with `setuptools<70` and `scikit-learn<=1.5.1` pins.
  - On this sample it found **1 note** (with ONNX and lowered thresholds), because the lead glides into every note.
- **`librosa.pyin` works well on this sample.** librosa 0.11 / 1.0 is already in the env via spectrum-advisor.
  - It is monophonic and 66 % voiced.
  - It shows the phrase clearly. Each bar holds three notes on beats 1, 2.5 and 4 (a 3-3-2 rhythm): **A#4, F#5, C#6**, an F# major arpeggio.
  - Each note **glides up 1–2 semitones** into its target: G#→A→A#, E→F→F#, B→C→C#.
- **Timbre:**
  - Harmonics relative to the fundamental: H2 −14 dB, H3 −1 dB, H4 −31 dB, H5 −21 dB, then −40 dB and lower. Odd harmonics dominate, so it is **square/pulse-like**, low-passed hard above about H5 (≈ 2.3 kHz on A#4).
  - Spectral centroid rises on the last note of each bar (1.4 → 3.9 kHz). That points to a filter or brightness envelope, or to the higher note.
  - Side/mid RMS 0.37: moderately wide, chorus/unison-like.
  - Spectral flatness ≈ 0: no noise.
- **Live 10 LOM** (used by ahujasid/ableton-mcp on Live 10): `song.create_midi_track(index)`, `clip_slot.create_clip(length)`, `clip.set_notes(((pitch, time, dur, vel, mute), ...))`, and `browser.instruments` with `load_item` on the selected track. No pitch-bend writing in Live 10, so glides come from the synth (glide/portamento with legato notes, or a pitch envelope).

## Acceptance Criteria

### AC-1: Sample analysis gives notes, rhythm and a synth recipe
- **Given**: a new `src/claude_mpc/sound.py` and synthetic test signals (numpy square/saw/sine notes at known pitches, rhythms, envelopes and glides)
- **When**: `uv run pytest tests/test_sound.py -q` runs
- **Then**:
  - `analyze_sample(path, tempo=None)` returns `{file, sr, duration_s, tempo, bars, notes, key, timbre, envelope, stereo}`.
  - **`notes`:**
    - monophonic pyin → note segments, `[{pitch, name, start_beat, length_beats, velocity, glide_from}]`;
    - quantised to 1/16 at the tempo;
    - `glide_from` is the pitch the note slides up/down from, or null.
  - **`tempo`:** given → used. Else read from the file name (`_172_`, `172bpm`). Else librosa's estimate.
  - **`key`:** a guess from the note pitch classes (e.g. "F# major"). The file name is a hint only.
  - **`timbre`:**
    - `osc`: sine | triangle | square | saw, from the odd/even harmonic balance;
    - `harmonics_db`: the first 8 harmonics;
    - `cutoff_hz`: where the harmonics fall 24 dB below the strongest one;
    - `brightness_move`: does the centroid change within notes, and by how much;
    - `noise`.
  - **`envelope`:** attack, decay and sustain level (0–1) and release, in ms, from the RMS around each note (median).
  - **`stereo`:** side/mid ratio → "mono" / "narrow" / "wide".
  - **Tests:**
    - a square arpeggio with glides is recovered: pitches, starts within 1/16, `glide_from` set;
    - square vs saw vs sine are told apart;
    - a mono vs wide signal;
    - the tempo is read from the file name;
    - a missing file, or silence, raises a clear error.
  - `find_sample(name)` returns the matching audio files: an absolute path, else Spotlight `mdfind -name` (mocked in tests).
- **Verify**: `uv run pytest tests/test_sound.py -q`

### AC-2: Build an instrument track in Live from MCP
- **Given**: Remote Script 0.6.0 and the MCP server with the fake Live
- **When**: the tests run
- **Then**:
  - **New command `create_instrument_track(name, instrument, index=None, clip=None)`:**
    - Validates first: the instrument must exist in `browser.instruments` (Operator, Analog, Wavetable, …), and clip notes must have a pitch of 0–127, start ≥ 0, length > 0, and lie within the clip length.
    - Then, as **one undo step**:
      - `create_midi_track(index)` (default: right after the last track);
      - names it;
      - loads the instrument onto it, restoring the user's selection;
      - with `clip={length_beats, name, notes:[{pitch, start_beat, length_beats, velocity}]}`, creates the clip in slot 0 and `set_notes`.
    - Returns `{track_index, track, device, clip}`.
  - **The usual `apply` handles the rest:** synth params, `load_effect` and Phase 7 automation all work on the new `track_index`.
  - **MCP tools:**
    - `analyze_sample(path_or_name, tempo=None)`, read-only: allowlisted like `get_session`, runs in `asyncio.to_thread`;
    - `create_instrument_track(...)`, a write tool: not allowlisted.
  - **The `create_instrument_track` docstring gives Claude a recipe that turns the analysis into settings:**
    - `osc` → the synth waveform;
    - `cutoff_hz` → filter frequency;
    - `brightness_move` → filter envelope amount;
    - the envelope → amp ADSR;
    - `glide_from` → glide/portamento with legato (overlapping) notes, or a pitch envelope;
    - stereo → Chorus / unison;
    - propose → confirm;
    - read the synth's params with `get_device_params` first, because display names differ per synth.
  - `SCRIPT_VERSION = "0.6.0"`; the py27 compat test covers the new code.
  - `uv run pytest -q` is all green, including the Phase 1–7 tests.
- **Verify**: `uv run pytest -q`

### AC-3: Live UAT, the test sample reproduced
- **Given**: Remote Script 0.6.0 installed, Live restarted, `/mcp` Reconnect
- **When**: Dorian says "reproduce the sample on the test track"
- **Then**:
  - Claude finds and analyses the file, then shows what it hears: notes, rhythm, key, timbre, envelope.
  - Claude proposes the synth, settings and effects. Dorian confirms.
  - Claude builds the track: instrument, notes clip, params, effects. Optional: Phase 7 automation where the brightness moves.
  - Dorian A/Bs the clip against the sample:
    - the **notes and rhythm match**;
    - the sound is **in the same family** (square-ish lead, glides, filtered, some width);
    - it is a usable starting point.
  - Undo: Cmd+Z removes the param batch, then the track (or Dorian deletes the track).
- **Verify**: Dorian's verdict, recorded in `docs/UAT-phase8.md`

## Boundaries
- **DO NOT CHANGE**:
  - The wire protocol framing and `transport.py`.
  - Existing commands, op shapes and tool signatures (additions only).
  - The Phase 7 recorder/curves behaviour.
  - `../spectrum-advisor`.
  - Control Surface slot 1.
  - `.claude/settings.json`, except allowlisting the read-only `analyze_sample`.
- **OUT OF SCOPE**:
  - Polyphonic transcription (chords, pads) and basic-pitch.
  - Separating full loops or mixes (drums + bass + …).
  - Writing Arrangement clips (Live 10 has no API), so the pattern is a session clip.
  - Parsing `.als` files.
  - Third-party synths.
  - Sampler/Simpler resampling of the original.
  - Automatic matching or iteration loops (no "render and compare"). Dorian judges by ear.

## Risks
- **Glides:** Live 10 can't write pitch bend.
  - Mitigation: synth glide/portamento with legato (overlapping) notes. In Analog that's Glide + Legato; in Operator, Glide plus the pitch envelope. If neither sounds close enough, use a short pitch-envelope rise per note.
- **Synth param names differ per synth.** Claude reads them with `get_device_params` before setting them, and the docstring says so.
- **`load_item` for an instrument on a freshly created track** (selection timing inside one tick) is untested.
  - Fallback: create the track in one tick and load the instrument in the next, as two commands, which means two undo steps.
- **pyin octave errors or split notes** on other samples. Mitigation: median filtering, a minimum note length of 1/16, and confirming the transcription with Dorian before building.
