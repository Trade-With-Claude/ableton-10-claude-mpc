# PLAN — Phase 3: Mixer & Device Control

## Goal
Claude can change the mix, and every change can be undone. The write tools are `set_mixer`, `set_device_param`, `load_effect` (stock), `delete_device`, and a batch `apply` that runs as **one Live undo step**. Values can be given in display units (dB, Hz, %, item names), are clamped to range, and are read back after writing. Write tools always ask for permission in Claude Code (propose → confirm → apply).

## Acceptance Criteria

### AC-1: Write logic is correct and atomic against a fake LOM
- **Given**: a pure `ops.py` module (no `Live` import, py2.7/3) and fake LOM objects that record `begin_undo_step`/`end_undo_step`
- **When**: it applies a batch with: volume `-6 dB` on a track, pan `25L`, a send by return name, mute; a device param set by name using a display value (`Threshold -12 dB`), a quantized param by item name, an out-of-range value; a stock effect load and a device delete
- **Then**:
  - Values are clamped to min/max.
  - Display units are converted by bisection on `str_for_value` (`-inf` handled), and ambiguous or unknown param names fail with a candidate list.
  - **All ops are validated before any write**, so one bad op means nothing is applied.
  - Exactly one `begin_undo_step`/`end_undo_step` pair wraps the batch, and `end_undo_step` runs even if an op raises mid-batch.
  - Each op reports `{before, after}` display strings.
- **Verify**: `uv run pytest tests/test_ops.py -q`

### AC-2: MCP write tools are wired end to end, and only reads are allowlisted
- **Given**: the FastMCP server and `FakeLive` with `apply` routed through `ops.py`
- **When**: `set_mixer`, `set_device_param`, `load_effect`, `delete_device` and `apply` are called
- **Then**:
  - Every single-op tool goes through the same `apply` command, so it is also one undo step.
  - Errors surface as tool errors.
  - `.claude/settings.json` allowlists only the 4 read tools, so the write tools prompt.
  - `spike_load_effect` is removed.
  - The py2.7 guard covers `ops.py`.
- **Verify**: `uv run pytest -q` is all green; `grep -c spike_load_effect -r remote_script src scripts` returns 0

### AC-3: A proposed batch is approved, applied in Live, and reverted with one Cmd+Z
- **Given**: script 0.3.0 installed and a real DnB session open
- **When**: Claude proposes a batch on the DRUMS bus (volume, a send, a Glue Compressor param, and loading EQ Eight at the end of the chain), Dorian approves the permission prompt, and Claude applies it
- **Then**:
  - Live shows exactly those changes.
  - `get_device_params`/`get_session` read the new values back.
  - The user's track/device selection is restored.
  - **One Cmd+Z** reverts the whole batch. If `load_item` turns out to be its own undo step, that is recorded with the exact Cmd+Z count.
- **Verify**: manual UAT, recorded in `docs/UAT-phase3.md`

## Tasks

### Task 1: Pure write logic (`ops.py`) with fake-LOM tests
- **Files**: `remote_script/ClaudeMPC/ops.py`, `tests/fake_lom.py`, `tests/test_ops.py`, `tests/test_py27_compat.py`
- **Action**: Write `ops.py` with no `Live` import. It reuses `lom.resolve_track`/`resolve_device`/`_display`/`_text`.
  - `find_param(device, name_or_index)`: an int is an index; a string is a case-insensitive exact match, else a unique substring match. Otherwise raise with the candidates.
  - `value_for(param, value=None, display=None)`:
    - `value` is raw and gets clamped.
    - `display` is a number in display units. Bisect over [min, max] for ~40 iterations, parsing the leading float of `str_for_value`, where `-inf` → −∞. Monotonic direction is auto-detected.
    - Quantized params accept an item name or an index.
    - Bool strings `on`/`off` are accepted for 2-item params.
    - Pan accepts `"25L"`/`"C"`/`"10R"` via the display path.
  - Op schema: `{op: "mixer"|"param"|"load_effect"|"delete_device", kind, index, ...}`.
    - `mixer` takes `volume_db`/`volume`, `pan`, `sends: {return name|letter|index: dB}`, `mute`, `solo`. Master has volume/pan only.
    - `param` takes `path`, `param`, and `value`/`display`.
    - `load_effect` takes `name` and `position` (default: end).
    - `delete_device` takes `path`.
  - `plan(song, ops)` resolves and validates everything with no writes, returning bound closures.
  - `apply(song, ops, loader)` calls `plan()`, then `song.begin_undo_step()`, runs the closures, and calls `end_undo_step()` in `finally`. It returns `[{op, target, before, after}]` plus `applied`/`error` if it fails mid-batch.
  - `loader(track, name, position)` is injected, so the browser/`Live` enum code stays in `commands.py`. `delete_device` uses `track.delete_device(i)`, or `chain.delete_device(i)` inside racks.
  - Extend the fakes with `Song.begin/end_undo_step` counters, `delete_device`, settable mixer params, and a fake loader. Add `ops.py` to the 2.7/3.0 compat guard.
- **Verify**: `uv run pytest tests/test_ops.py tests/test_py27_compat.py -q` is green
- **Done**: true

## Research Done
- Live 10.1.43 ships `pushbase/undo_step_handler.pyc`, which calls `song.begin_undo_step()`/`end_undo_step()`. The API exists in Live 10, so `apply` can group writes into one undo step.
- Phase 1 spike (`docs/SPIKES.md`): `load_item` works on master/returns with selection restore, and each load was its own undo step **without** begin/end. Whether `load_item` joins an open undo step is unknown, and AC-3 measures it.
- Live mixer volume is a normalized 0–1 param (0.85 = 0 dB), so dB input needs `str_for_value` inversion (bisection) rather than a hard-coded curve.
- Real sessions have duplicate track names (Phase 2 UAT), so ops address tracks by kind/index only.
