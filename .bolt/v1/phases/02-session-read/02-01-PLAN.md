# PLAN — Phase 2: Session Read

## Goal
Claude can see the whole Live session through three read-only MCP tools: `get_session`, `get_device_params` and `get_meters`. The output covers group/bus structure, returns, master, mixer state, device chains (racks included) and full parameter detail for both stock and third-party devices. Serialization is Unicode-safe and every object uses stable kind/index addressing.

## Acceptance Criteria

### AC-1: Serializers are correct and Unicode-safe against a fake LOM
- **Given**: a pure `lom.py` module (no `Live` import) and duck-typed fake LOM objects in tests
- **When**: it serializes a session with a group containing 2 tracks, 2 returns, master, a rack with nested chains, a quantized param, a plugin, and names like `Bässe ✦ Sub`
- **Then**: `group_index`/`is_foldable` reflect the hierarchy, sends are named after their returns, display strings come from `str_for_value`, nested rack devices are reachable by `device_path`, non-ASCII names round-trip through `json.dumps` → utf-8 → `json.loads`, and bad addresses raise clear errors (`no return track 5 (have 2)`)
- **Verify**: `uv run pytest tests/test_lom.py -q`

### AC-2: MCP tools are wired end to end against the fake Live
- **Given**: the FastMCP server and an extended `FakeLive` with `get_session` / `get_device_params` / `get_meters` handlers
- **When**: each tool is called (including `get_meters(reads=3)` peak-hold and `get_device_params(query=...)`)
- **Then**: results pass through with the documented shape, and Live errors surface as tool errors
- **Verify**: `uv run pytest -q` is all green (Phase 1 tests included), and the py2.7 guard covers `lom.py` (2.7 and 3.0)

### AC-3: Claude describes a real DnB session accurately
- **Given**: the script is reinstalled and one of Dorian's real DnB sessions is open in Live 10.1.43
- **When**: Claude calls `get_session`, then `get_device_params` on a stock device (e.g. Glue Compressor on the drum bus) and on a third-party plugin, then `get_meters` during playback
- **Then**: Dorian confirms the bus structure, returns/sends, master chain and param values (including display strings like "-12.0 dB") are correct. `get_session` takes ≤ ~1 tick of extra latency and Live doesn't stutter
- **Verify**: manual UAT, recorded in `docs/UAT-phase2.md` (session size, timings, any mismatches)

## Tasks

### Task 1: Pure LOM serializers + addressing (`lom.py`) with fake-LOM tests
- **Files**: `remote_script/ClaudeMPC/lom.py`, `tests/fake_lom.py`, `tests/test_lom.py`, `tests/test_py27_compat.py`
- **Action**: Write `lom.py` with no `Live` import, so it is py2.7 and py3 compatible and can be unit-tested. Add a `_text(x)` helper that is `unicode` on py2 and `str` on py3, and use it for every name.
  - `resolve_track(song, kind, index)` handles `track|return|master` and gives clear range errors. `resolve_device(track, path)` takes `path` as a list of ints `[dev]` or `[rack, chain, dev, …]`.
  - `serialize_session(song)` returns `{tempo, tracks, returns, master}`. Each track has: `index, name, color, kind(audio|midi|group), is_foldable, fold_state, group_index` (found by identity map), `output` (`output_routing_type.display_name`, try/except), `mute, solo, arm` (if `can_be_armed`), `volume`/`pan` as `{value, display}`, `sends` `[{return, value, display}]`, and `devices`.
  - Each device has: `path, name, class_name, type, is_plugin` (`PluginDevice`/`AuPluginDevice`), `on` (the "Device On" param), `n_params`. Racks add `chains: [{name, mute, solo, devices}]`, recursing up to depth 4. Master has no mute/solo/sends.
  - `serialize_params(device, query=None)` returns `[{index, name, value, min, max, is_quantized, value_items?, display, is_enabled}]`. `display` uses `str_for_value(value)` with a `_text(param)` fallback.
  - `read_meters(song)` returns `{kind,index,name,left,right}` for tracks with `has_audio_output`, as raw 0–1 meter values.
  - Fakes cover the AC-1 cases. Extend the compat guard so `lom.py` is checked for both 2.7 and 3.0.
- **Verify**: `uv run pytest tests/test_lom.py tests/test_py27_compat.py -q` is green
- **Done**: true

## Boundaries

## Research Done
None needed. The Live 10 LOM read API (Track/MixerDevice/Device/RackDevice chains/DeviceParameter `str_for_value`, `output_meter_left/right`, `group_track`, `output_routing_type`) is well known, and Phase 1 proved the bridge. Uncertain attributes (`output_routing_type`, meter scale) are wrapped in try/except, and UAT confirms how they behave.
