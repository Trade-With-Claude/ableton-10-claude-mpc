# PLAN — Phase 7: Automation from Vibes

## Goal
Dorian describes a movement in words ("filter slowly opening over 16 bars, a dip before the drop"). Claude turns it into
curves on device parameters and writes them as **real, editable Arrangement automation** by recording them: the Remote
Script plays the curve on the parameter, in time with Live's song position, while Arrangement record and Automation Arm
are on. Live 10's API cannot write Arrangement automation directly (that came with Live 11), so recording is the way in.

## Acceptance Criteria

### AC-1: Curves and the recorder work against the fake LOM
- **Given**: the new `remote_script/ClaudeMPC/curves.py` and `remote_script/ClaudeMPC/recorder.py`, with a fake song
  whose `current_song_time` the test advances tick by tick
- **When**: the unit tests run
- **Then**:
  - **Curves** (`curves.py`, pure). A lane is a list of segments in bars:
    `{"from_bar", "to_bar", "shape", "start", "end", "rate", "depth"}`.
    - Shapes: `ramp` (linear), `exp` (slow start, fast end), `log` (fast start, slow end), `hold`, `sine` / `triangle` /
      `square` (LFO around `start`↔`end` at `rate` such as `"1/2"`, `"1"`, `"2"` bars), and `steps`
      (`"values": [...]`, one per `rate`).
    - Endpoints are given in display units (`2000`, `"1.2 kHz"`, `-6`, `"30 %"`) and converted once with `ops.value_for`.
      Interpolation runs in **raw** space, so Auto Filter frequency moves musically (its raw scale is already logarithmic).
    - `value_at(lane, beat)` is tested at segment starts, ends and midpoints, and between segments (the last value holds).
    - Validation rejects: overlapping segments, `to_bar <= from_bar`, an unknown shape, and an LFO period shorter than
      `MIN_PERIOD_TICKS` (4) ticks at the current tempo. The last one gives the message "too fast to draw at ~10 points/s:
      automate the device's own LFO (rate/amount) instead".
  - **Recorder** (`recorder.py`): a state machine driven by `tick()` from `update_display`.
    - `start(song, lanes, start_bar, bars, preroll_bars=1)`:
      - validates every lane;
      - refuses if a target param already has automation (`automation_state != 0`) unless `overwrite=True`;
      - refuses if Live is already playing or recording.
    - Then it snapshots, and later restores: `record_mode`, `session_automation_record` (Automation Arm), `loop`,
      `current_song_time`, and every track's `arm`.
    - It **disarms all tracks**, so no audio or MIDI gets recorded. Track 28 in Dorian's set is armed.
    - It turns the loop off, sets each param to its curve value at `start_bar`, moves the playhead to
      `start_bar - preroll_bars`, turns Automation Arm on and starts playback.
    - Each tick: when `current_song_time` reaches the start beat, it punches in (`record_mode = True`). While inside
      `[start, end)` it writes `value_at` to each param. At or after the end beat it punches out, stops playback and
      restores the snapshot.
    - `abort()` and any exception go through the same restore. Restore runs even if a step of it fails.
    - `status()` returns `{state: idle|preroll|recording|done|aborted|error, bar, progress, points_written,
      ticks, mean_tick_ms, error}`.
  - **Commands** (`commands.py`): `automation_record`, `automation_status`, `automation_abort`.
    `SCRIPT_VERSION = "0.5.0"`. `ClaudeMPC.update_display` calls `commands.tick()` after `poll()`.
  - `tests/test_py27_compat.py` covers the new modules.
- **Verify**: `uv run pytest tests/test_curves.py tests/test_recorder.py tests/test_py27_compat.py -q` is green

### AC-2: `record_automation` MCP tool
- **Given**: `src/claude_mpc/server.py` with the fake Live client
- **When**: `record_automation(lanes, start_bar, bars, preroll_bars=1, overwrite=False)` runs
- **Then**:
  - It sends `automation_record`, then polls `automation_status` every 250 ms until the state is `done`, `aborted` or
    `error`. The timeout is the expected duration (`(bars + preroll_bars) * 4 * 60 / tempo`) + 5 s.
  - It returns the final status plus `elapsed_s`.
  - On timeout or cancellation it sends `automation_abort` in a `finally`.
  - Each lane is addressed like `set_device_param`: `{kind, index, device_path, param, segments}`.
  - The docstring explains the following, so Claude uses it well:
    - how to turn a "vibe" into segments (shape vocabulary, bar ranges);
    - propose → confirm, and naming the bars;
    - loading the effect first with `load_effect`/`apply` if it isn't there;
    - fast wobbles (under ~1/2 bar at 175 BPM) belong on the device's own LFO;
    - **one Cmd+Z (with Live focused) removes the take**, if the UAT confirms it;
    - existing automation on the param is refused unless `overwrite`.
  - `uv run pytest -q` is all green (including the Phase 1–5 tests).
- **Verify**: `uv run pytest -q`

## Boundaries
- **DO NOT CHANGE**:
  - The wire protocol framing and `transport.py`.
  - Existing commands, op shapes and tool signatures. The new tools and commands are additions only.
  - `.claude/settings.json`: write tools stay non-allowlisted.
  - `../spectrum-advisor`.
  - Control Surface slot 1.
- **OUT OF SCOPE**:
  - Session clip envelopes (`clip.automation_envelope`), except as the fallback.
  - Mixer volume/pan/send lanes. Device params only this phase; mixer lanes are an easy follow-up.
  - Editing or deleting existing Arrangement automation (Live 10 has no API for it). Undo is the way back.
  - Time signatures other than 4/4.
  - Sound reproduction (Phase 8).

## Risks
- **Live may not record script-made changes** in the Arrangement. **De-risked 2026-10-20 (pre-build spike):** with
  Automation Arm + Arrangement record on, 5 `set_device_param` calls on Auto Filter Frequency (track "test") were
  recorded as a stepped automation curve on 10.1.43. Task 3 step 1 still measures tick rate, breakpoints and undo. **Fallback:** draw the curve into a session clip's
  envelope (`clip.automation_envelope` + `insert_step`, exact points), then Dorian records the session clip into the
  Arrangement, or keeps it as a clip envelope.
- **Tick resolution (~10 Hz)** gives about 3 points per beat at 175 BPM: fine for ramps and dips, too coarse for fast
  LFOs. Validation enforces a minimum period and steers Claude to device LFOs. If Live thins the recorded points, the
  ramps stay smooth anyway.
- **Recording side effects:**
  - Arrangement record also records armed tracks. All tracks are disarmed and restored.
  - Session clips playing would override the Arrangement. The tool refuses if `back_to_arranger` is lit.
  - A crash mid-take leaves record on. `_restore` runs on abort, error and Live stop; a manual Cmd+Z / record-off is the
    last resort.
- **Overwriting:** recording over a param that already has automation replaces it in that range. It's refused unless
  `overwrite=True`, and Claude must say so in the proposal.
