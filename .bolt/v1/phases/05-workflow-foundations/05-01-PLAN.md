# PLAN — Phase 5: Workflow Foundations

## Goal
Fix what the Phase 4 UAT showed is missing before the DnB workflow (now Phase 6) can lean on it.
- **Plugin values set right:** `display` values on third-party plugins that show a typographic minus (U+2212) are set correctly.
- **Clean captures:** `analyze_master` starts Live's playback itself, waits a pre-roll, records, stops what it started, and rejects captures that are partly silent instead of reporting wrong numbers.
- **Racks become editable:** Claude can read and set a rack chain's volume/pan/mute/solo, and load a stock effect *inside* a rack chain.
- **Folding is kept:** loading a device no longer leaves folded groups unfolded.

## Acceptance Criteria

### AC-1: Remote Script logic covers minus signs, rack chains, fold state and transport (fake LOM)
- **Given**: `remote_script/ClaudeMPC/{ops,lom,commands}.py` with the fake LOM in `tests/fake_lom.py`
- **When**: the unit tests run
- **Then**:
  - **Minus signs:**
    - `parse_display(u"−0.51 dB") == -0.51`. The en dash `–` is handled the same way.
    - A kHs-Limiter-like param (raw 0..1 → −20..+20 dB, displayed with U+2212) set with `display: -1` lands at raw ≈ 0.475 and reads back `−1.0x dB`. It does *not* land at −20.
  - **Chain mixer:**
    - `get_session` / `serialize_device` chain entries now carry `volume` and `pan` as `{value, display}`, from `chain.mixer_device`. The entries are omitted if the chain has no mixer.
    - A new op `{"op": "chain_mixer", "kind", "index", "chain": [rack path..., chain_idx], "volume_db", "pan", "mute", "solo"}` validates like `mixer`, and applies inside the batch undo step.
  - **Load into a chain:**
    - `load_effect` accepts an optional `"chain": [rack path..., chain_idx]`, with `position` counted within that chain.
    - Validation rejects:
      - a bad chain path, with a clear error;
      - a non-rack;
      - an **empty chain** ("can't load into an empty chain yet: add any device to it first"). Live 10 can only insert next to a selected device.
  - **Loader plan:** the pure helper `ops.insert_plan(devices, position)` returns (neighbour, mode) for the end, the start and the middle. It's unit-tested; `EffectLoader` uses it for both track and chain targets.
  - **Fold state:** the pure helper `lom.fold_snapshot(track)` / `lom.restore_folds(snapshot)` covers the target track and every ancestor group. Unit tests check that a folded parent group is re-folded after a simulated unfold.
  - **Transport:**
    - `ping` reports `is_playing`.
    - The new command `transport {"play": bool}` calls `song.start_playing()` / `song.stop_playing()` and returns `{is_playing}`.
  - `tests/test_py27_compat.py` still passes, so the code stays py2.7-safe.
- **Verify**: `uv run pytest tests/test_ops.py tests/test_lom.py tests/test_py27_compat.py -q` is green

### AC-2: `analyze_master` controls playback and rejects partial captures
- **Given**: `src/claude_mpc/{server,analysis}.py` with the Live client and `capture.record` mocked
- **When**: `analyze_master(seconds, reference, autoplay=True)` runs
- **Then**:
  - **Autoplay:**
    - If `ping.is_playing` is false, it calls `transport(play=True)`, waits a pre-roll (`PREROLL_S = 1.0`), records, then calls `transport(play=False)`. The stop runs in a `finally`, so it also happens on errors.
    - If Live was already playing, it touches nothing.
    - `autoplay=False` keeps the Phase 4 behaviour.
    - The result carries `"autoplay": "started"|"already_playing"|"off"`.
  - **Silence coverage:** `analysis.silence_fraction(frames, sr)` measures the share of 100 ms windows below −60 dBFS (RMS). If it's above 10 %, the tool returns an `AnalysisError` naming the percentage and the likely cause (playback started late or stopped, or a breakdown in the loop). A capture with no signal at all still gives the existing "No signal on BlackHole 2ch…" error. The fraction is reported in the result as `silence_fraction`.
  - **Docstrings:**
    - `get_session` mentions chain `volume`/`pan`.
    - `apply` documents `chain_mixer` and `load_effect.chain`.
    - `analyze_master` says Claude can call it with Live stopped; it plays from Live's insert marker and loop, so Dorian sets the loop on the drop.
  - `uv run pytest -q` is all green (including the Phase 1–4 tests).
- **Verify**: `uv run pytest -q`

  - No UI stutter.

## Tasks

### Task 1: Remote Script — minus fix, chain mixer and chain loads, fold restore, transport
- **Files**: `remote_script/ClaudeMPC/ops.py`, `remote_script/ClaudeMPC/lom.py`, `remote_script/ClaudeMPC/commands.py`, `tests/fake_lom.py`, `tests/test_ops.py`, `tests/test_lom.py`
- **Action**:
  - **`ops.parse_display`:** normalise `u"−"`, `u"–"` → `-` before matching. Add the kHs-like fake param and the tests.
  - **`lom.py`:**
    - Chain entries in `serialize_device` get `volume`/`pan` via `_param_value(chain.mixer_device.volume/panning)`, inside try/except.
    - Add `resolve_chain(track, chain_path)`: an even-length path, whose last element is the chain index and whose prefix is the rack's device path. It errors if the target isn't a rack.
    - Add `fold_snapshot(track)`, which walks `track` + `group_track` ancestors and records `(group, fold_state)` for foldable ones, and `restore_folds(snapshot)`, which sets them back and ignores failures.
  - **`ops.py`:**
    - `insert_plan(devices, position)` → `(neighbour_index|None, "default"|"selected_left"|"selected_right")`, the same logic as today's `EffectLoader.load`.
    - `_plan_load` accepts `op["chain"]`: it resolves the chain, rejects an empty chain, range-checks `position` against the chain's devices, and calls `loader.load(track, name, position, chain=chain)`.
    - New `_plan_chain_mixer`: volume/pan through `value_for` on `chain.mixer_device`, mute/solo as attrs on the chain.
    - Register `chain_mixer` in `plan()` and in the unknown-op message.
  - **`commands.py`:**
    - `SCRIPT_VERSION = "0.4.0"`.
    - `ping` adds `is_playing`.
    - New `transport(play)` command.
    - `EffectLoader.load(track, name, position=None, chain=None)`:
      - Takes the devices from `chain.devices` if a chain is given, and uses `ops.insert_plan`.
      - Takes `lom.fold_snapshot(track)` before selecting and restores it in `finally`.
      - Detects the new device in the chain when a chain is given. If Live put it anywhere else on the track, it deletes the stray device and raises "Live loaded X outside the chain".
  - **`FakeLoader`:** accepts `chain=`. The fake Chain gets a `mixer_device`.
- **Verify**: `uv run pytest tests/test_ops.py tests/test_lom.py tests/test_py27_compat.py -q` is green

## Boundaries
- **DO NOT CHANGE**:
  - `../spectrum-advisor`: no changes this phase. The silence check lives in claude-mpc.
  - The wire protocol framing and `transport.py`.
  - The existing op shapes: only optional fields and the new op are added, so Phase 3 batches still validate unchanged.
  - The read tools' allowlist semantics, and `.claude/settings.json`. `analyze_master` stays allowlisted: autoplay only starts and stops playback the tool itself began.
  - Control Surface slot 1.
- **OUT OF SCOPE**:
  - DnB chain presets, auto gain staging and teaching explanations (Phase 6).
  - Meter auto-unfold (Phase 6, together with gain staging).
  - A "Reference" track as the analysis reference. Live 10 has no arrangement-clip API (`arrangement_clips` is Live 11+), so this needs research. It goes to Phase 6 or 7.
  - The spectrum-advisor low-band FFT fix (20/40 Hz bands empty) and pump-score stability (Phase 7, or spectrum-advisor's own backlog).
  - Loading into an *empty* rack chain, and rack return-chain sends.
  - A separate play/stop MCP tool.

## Risks
- **`select_device` on a nested device:** `load_item` may not insert next to a device that is selected inside a chain. The loader detects a misplaced device, deletes it and errors, so nothing silently lands in the wrong place. The UAT (step 4) settles it.
- **Where `start_playing()` plays from:** it plays from the insert marker. If the loop and insert marker aren't on the drop, the capture is of the wrong section. The docstring tells Claude to ask Dorian to set the loop.
