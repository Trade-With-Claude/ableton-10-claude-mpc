# PLAN — Phase 1: Bridge Foundation

## Goal
A threadless Py2.7 Remote Script (`ClaudeMPC`) runs inside Live 10.1.43. A Py3.13 FastMCP server reaches it over localhost TCP with newline JSON, and `ping` works end to end from Claude Code. Phase 1 also runs the early spikes: latency/stability, and loading FX onto master and a return.

## Acceptance Criteria

### AC-1: Protocol works against a fake Live
- **Given**: the MCP server package and a pytest fake-Live socket stub
- **When**: the client sends `ping`, an unknown command, a malformed line, and a response large enough to force partial writes
- **Then**: it gets `{id, ok:true, result}`, `{id, ok:false, error}`, a clean error, and the full payload respectively
- **Verify**: `uv run pytest` passes

### AC-2: Remote Script stays Python 2.7 compatible
- **Given**: `remote_script/ClaudeMPC/*.py`
- **When**: the syntax guard runs
- **Then**: no py3-only syntax or stdlib (f-strings, `nonlocal`, type hints, etc.) is found, and there are no threads
- **Verify**: `uv run pytest tests/test_py27_compat.py` (vermin `-t=2.7-` plus a grep for `threading`)

### AC-3: ping from Claude Code via real Live
- **Given**: the script is installed via `scripts/install.sh`, selected in a free Control Surface slot, and the MCP server is registered in Claude Code
- **When**: Claude calls the `ping` tool
- **Then**: it returns Live's version and tempo in ≤ ~200 ms, and the Live UI stays smooth
- **Verify**: manual UAT; the round-trip times are recorded in `docs/SPIKES.md`

### AC-4: Spikes documented
- **Given**: a dev-only `spike_load_effect` command
- **When**: it loads Utility onto master and onto Return A, and a 100-ping burst is timed
- **Then**: the results (success or failure, selection restored, p50/p95 latency, any UI stutter) are written down
- **Verify**: `docs/SPIKES.md` exists with the results and a go/no-go for the Phase 3 approach

## Tasks

### Task 1: MCP server skeleton + protocol + fake-Live tests
- **Files**: `pyproject.toml`, `src/claude_mpc/__init__.py`, `src/claude_mpc/protocol.py`, `src/claude_mpc/client.py`, `src/claude_mpc/server.py`, `tests/conftest.py`, `tests/fake_live.py`, `tests/test_client.py`, `.gitignore`
- **Action**: `uv init` a Py3.13 package (deps: `mcp`; dev: `pytest`, `vermin`). `protocol.py` encodes and decodes newline JSON `{id, cmd, params}` / `{id, ok, result|error}`. `client.py` is a `LiveClient` with a lazy TCP connect to `127.0.0.1:9879`, per-request ids, a timeout (default 5 s), and a reconnect attempt on a broken pipe. `server.py` is a FastMCP app (stdio) with a `ping` tool that returns the result plus measured `rtt_ms`. `fake_live.py` is a threaded socket server that echoes the protocol, including a chunked-write mode. Tests cover AC-1.
- **Verify**: `uv run pytest -q` is green, and `uv run claude-mpc --help` (or an import) runs
- **Done**: true

### Task 2: Threadless Remote Script + install + py2.7 guard
- **Files**: `remote_script/ClaudeMPC/__init__.py`, `remote_script/ClaudeMPC/ClaudeMPC.py`, `remote_script/ClaudeMPC/transport.py`, `remote_script/ClaudeMPC/commands.py`, `scripts/install.sh`, `tests/test_py27_compat.py`, `tests/test_transport_logic.py`
- **Action**: The `ControlSurface` subclass binds a non-blocking listen socket on `127.0.0.1:9879` in `__init__`. In `update_display()` it does `select(timeout=0)`: accept, read and split lines, dispatch up to N commands per tick, then flush per-client out-buffers with `send()` and keep the remainder (partial-write safe). `disconnect()` closes all sockets. Commands: `ping` → `{live_version, tempo, script_version}`; `spike_load_effect {target: master|return, index, name}` uses the browser `audio_effects` walk, clears hotswap, inserts `selected_right`, and restores the selection. Errors are caught per command so they never crash the surface, and each one gets a `log_message`. Py2-only idioms: no f-strings, `u''`/`unicode()`. `transport.py` stays pure (no Live imports) so pytest under py3 can unit-test the buffering logic. `install.sh` rsyncs to `~/Music/Ableton/User Library/Remote Scripts/ClaudeMPC/`, deletes stale `.pyc` files, and prints the reminder to restart Live / re-select the surface.
- **Verify**: `uv run pytest -q` (compat + transport tests) is green, and `scripts/install.sh` copies the files
- **Done**: true

### Task 3: Live UAT + spikes write-up
- **Files**: `scripts/spike_latency.py`, `docs/SPIKES.md`, `.mcp.json` (project-scoped MCP registration), `.claude/settings.json` (allowlist `ping`)
- **Action**: Register the server in Claude Code (`uv run claude-mpc`). Dorian selects ClaudeMPC in a free slot (2–6). `spike_latency.py` sends 100 pings and reports p50/p95/max. Run `spike_load_effect` on master and Return A, and check the selection is restored and Cmd+Z works. Record everything, including Live's `Log.txt` excerpts, in `SPIKES.md` with a go/no-go for the Phase 3 `load_effect` approach.
- **Verify**: The `ping` tool works in a Claude Code chat, and `docs/SPIKES.md` holds real numbers
- **Done**: false
